# Architecture

## Overview

DeFi Risk Intelligence Platform is a fully client-side React application. There is no application backend — all data flows happen directly from the browser to public APIs and the Arc Testnet blockchain. The only server-side component is the on-chain `RiskReceiptRegistry` smart contract deployed on Arc Testnet.

```
Browser (Vite + React)
  ├── DefiLlama API           → live TVL / category / chain data
  ├── Arc Testnet RPC         → read/write RiskReceiptRegistry contract
  ├── ConnectKit + wagmi      → wallet connection & transaction signing
  └── URL params              → shareable protocol links & receipt snapshots
```

## Data Flow

### Protocol Loading

1. `useProtocols` hook fires on mount, calling `fetchProtocols()` from `lib/defiLlama.ts`
2. DefiLlama `/api/protocols` is fetched client-side (CORS-open public API)
3. Protocols are filtered (TVL > $1M, DeFi category), ranked, and mapped to the internal `Protocol` shape with algorithmically derived risk scores
4. If the fetch fails, the static fallback in `data/protocols.ts` is used

### Risk Scoring

Each protocol receives scores on five axes: smart contract risk, liquidity risk, governance risk, oracle risk, and counterparty risk. Scores are derived from:
- Audit count and recency (from DefiLlama metadata)
- TVL size (larger = lower liquidity risk tier)
- Chain count (concentrated chains = higher counterparty risk)
- Protocol category (DEX, lending, bridge each carry different base risks)
- Protocol age (newer = higher contract risk)

A weighted composite (configurable via `WEIGHTS` in `data/protocols.ts`) produces a 0–100 final score. Higher = more risk.

### On-Chain Anchoring

1. User computes a SHA-256 hash of the JSON receipt in `ReceiptPanel`
2. `AnchorPanel` calls `anchorReceipt(bytes32 hash, string protocolRef)` on `RiskReceiptRegistry`
3. wagmi `useWriteContract` submits the transaction; `useWaitForTransactionReceipt` polls for confirmation
4. On success, the app auto-navigates to `VerifyPanel` with the hash pre-populated
5. `VerifyPanel` calls `getReceipt(bytes32 hash)` — a read-only call via `useReadContract`

### Premium Access

1. `usePremiumAccess(protocolId)` checks `localStorage` for a key `premium:<address>:<protocolId>`
2. If not found, `PremiumGate` renders a paywall: 1 USDC `transfer` to the treasury address on Arc Testnet
3. On transaction confirmation, `localStorage` is written and the gate lifts
4. Access persists per wallet-address + protocol pair across page reloads

### Shareable URLs

- `?protocol=<id>` — direct link to a protocol's detail view
- `?receipt=<base64>` — self-contained receipt snapshot (no server round-trip)

## Smart Contract

`RiskReceiptRegistry` (Arc Testnet: `0xf9394055a418cf0cf606c11c928d992bb1c55536`)

```solidity
function anchorReceipt(bytes32 hash, string calldata protocolRef) external
function getReceipt(bytes32 hash) external view returns (address, uint256, string memory)
```

One receipt per hash. Re-anchoring an existing hash reverts. The contract is ownable (OpenZeppelin) but anchoring is permissionless — any address can anchor.
