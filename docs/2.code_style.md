# Code Style

## Language & Toolchain

- **TypeScript** — strict mode enabled (`tsconfig.json`). No `any` without justification.
- **React 18** — function components only, hooks everywhere.
- **Bun** — package manager and script runner. Never use `npm` or `npx`; use `bun` and `bunx`.
- **Vite** — dev server and bundler.
- **oxlint** — linter (see `.oxlintrc.json`). Run `bun run check` before every commit.

---

## File & Folder Conventions

```
src/
  components/   One file per component. Name matches export: PremiumGate.tsx → export function PremiumGate
  hooks/        Custom React hooks. Prefix: use*
  lib/          Pure utility modules. No React imports.
  data/         Static data and domain logic (scoring engine, types).
```

- Component files: `PascalCase.tsx`
- Hook files: `camelCase.ts` with `use` prefix
- Utility/lib files: `camelCase.ts`
- Type-only files: `types.ts` or co-located with the module that owns them

---

## TypeScript Rules

- Always type function parameters and return values explicitly on exported functions
- Prefer `interface` for object shapes with known keys; `type` for unions and aliases
- No implicit `any` — the linter will catch it
- Use `unknown` instead of `any` when the type is genuinely unknown, then narrow it
- Mark unused parameters with a leading underscore: `_evidence`
- Use `as const` for literal arrays and objects that should not be widened

```ts
// Good
export function buildReceipt(protocol: Protocol): RiskReceipt { ... }

// Bad
export function buildReceipt(protocol) { ... }
```

## React Conventions

- All hooks at the top of the component, before any conditional logic
- No early returns before hooks (Rules of Hooks)
- `useCallback` and `useMemo` only when there is a measurable performance reason — not by default
- Prefer derived values over `useEffect` + `setState` for sync transformations
- Async side effects go in `useEffect` with a `void load()` pattern:

```ts
useEffect(() => {
  void (async () => {
    const data = await fetchSomething();
    setData(data);
  })();
}, [dep]);
```

- Event handlers that return promises use a `void` wrapper on the `onClick`:

```tsx
<button onClick={() => { void handleClick(); }}>Go</button>
```

## Styling

- **Tailwind CSS utility classes only** — no new `.css` files (except `index.css` which owns the Tailwind directives and CSS custom properties)
- CSS custom properties (`var(--ink-2)`, `var(--subtle)`, etc.) are defined in `index.css` and shared across components for the design token layer
- Mobile-first: start with `sm:` breakpoints and expand outward
- Interactive states: always include `hover:`, `focus-visible:`, `active:`, `disabled:` variants
- Animations: use `framer-motion` for meaningful transitions (gauges, bars); use Tailwind `transition-*` for micro-interactions (hover color, opacity)
- Never hardcode color hex values inline — map to design tokens or Tailwind palette names

```tsx
// Good
<div className="text-[var(--ink-2)] bg-[var(--surface-1)] rounded-xl border border-[var(--border)]">

// Bad
<div style={{ color: "#e2e8f0", background: "#1a1f2e" }}>
```

## Onchain Code Patterns

These rules apply to every file that touches blockchain state:

- Import chain facts from `@/onchain-facts`, never hardcode chain IDs, RPC URLs, or contract addresses in component code
- Import amount helpers from `@/onchain-money` — never call `parseUnits` / `formatUnits` directly on USDC paths
- Import terminal state helpers from `@/onchain-wait` — never write your own polling loop
- Contract addresses and ABIs live in `src/lib/registry.ts` — import from there everywhere
- Use wagmi v2 patterns: `useAccount`, `useWriteContract().writeContract`, `useWaitForTransactionReceipt`

## Naming

| Thing | Convention | Example |
|---|---|---|
| React component | PascalCase | `ProtocolBrowser` |
| Hook | camelCase with `use` | `usePremiumAccess` |
| Utility function | camelCase | `buildReceiptLink` |
| Constant | SCREAMING_SNAKE | `REGISTRY_ADDRESS` |
| Type / Interface | PascalCase | `RiskReceipt` |
| CSS var | kebab-case | `--surface-1` |
| Event handler | `handle` prefix | `handleAnchor` |

---

## Imports

Order (enforced loosely, follow the pattern):
1. React and React-ecosystem (`react`, `wagmi`, `viem`)
2. Third-party libraries (`lucide-react`, `framer-motion`)
3. Internal absolute (`@/onchain-facts`, `@/onchain-money`)
4. Internal relative (`./components/…`, `../lib/…`)

Use `@/` alias for `src/` imports in app code. Relative paths are fine within the same directory.

---

## Comments

- No inline `// TODO` in committed code — open a GitHub issue instead
- JSDoc on exported functions in `lib/` and `data/` when the purpose is non-obvious
- No commented-out code blocks — delete them
- Explain *why*, not *what*: the code shows what; comments show reasoning

---

## Running Checks

```bash
bun run check      # lint + typecheck together — must pass before commit
```

Warnings are acceptable. Errors block the commit.
